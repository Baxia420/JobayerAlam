## Overview

Moonblade is a browser-based 2D action combat game engineered from the ground up using raw HTML5 Canvas and vanilla JavaScript, without relying on third-party game engines or physics libraries. Built as a solo developer submission for the UTM Hackathon 2026, the project earned a **Top 5 Finalist** ranking.

The project demonstrates low-level systems programming in the browser: managing a custom game loop, deterministic fixed-timestep physics, velocity integration, sprite state management, and multi-phase boss fight state machines.

## Problem

Modern web game development often leans on heavy engines like Phaser, Pixi.js, or Unity WebGL exports. While powerful, these frameworks introduce substantial bundle overhead, multi-second loading screens, and abstracted physics engines that make fine-grained control over attack frames and parry timing difficult to customize.

For a fast-paced samurai action game, combat responsiveness is everything. Even slight frame pacing hiccups or imprecise collision boxes destroy the feeling of impact. The challenge was to build a fluid, zero-dependency 60 FPS combat game that loads instantaneously in any modern browser while supporting multi-layered parallax environments, scripted cutscenes, and complex enemy AI.

## Approach

Rather than adapting an off-the-shelf engine, I implemented a bare-metal game architecture centered around three engineering principles:

1. **Fixed-Timestep Physics Loop:** Decoupled game simulation updates from browser render calls using an accumulator-based fixed-timestep pattern (`1/60s`), guaranteeing consistent movement physics and collision checks regardless of device monitor refresh rates (60Hz, 120Hz, or 144Hz).
2. **Deterministic Hitbox / Hurtbox Pipeline:** Built frame-accurate attack active windows with directional knockback vectors and parry frames, allowing precise melee interactions.
3. **Data-Driven Level &amp; Boss Configurations:** Decoupled animation frames, enemy attack tables, dialogue triggers, and parallax scroll coefficients into structured data objects rather than hardcoded imperative logic.

## Technical Implementation

- **Custom Game Engine Loop:** Implemented a `requestAnimationFrame` loop that calculates elapsed delta time, feeding an accumulator to run fixed physics updates (`dt = 16.67ms`) before interpolating render states.
- **Combat &amp; Collision Systems:** Programmed Axis-Aligned Bounding Box (AABB) intersection algorithms optimized for spatial sorting, distinct attack hitbox lifecycles, invulnerability frames, and combo chaining mechanics.
- **Entity &amp; Enemy AI State Machines:** Built modular finite-state machines for player actions (idle, dash, slash, parry, hurt) and boss behaviors. Bosses dynamically alternate between gap-closers, area-of-effect telegraphs, and defensive stances based on player distance.
- **Canvas Rendering &amp; Parallax:** Developed a multi-layered 2D rendering pipeline featuring background parallax scrolling, dynamic camera bounds with screen shake, and custom canvas-rendered UI elements (health meters, dialogue overlays, portrait cutscenes).

## Challenges

- **Frame Pacing &amp; Delta Timing:** High-refresh-rate displays (120Hz/144Hz) caused player movement to accelerate wildly under naive delta-time updates. Transitioning to a strict fixed-timestep update loop with render state interpolation resolved timing inconsistencies and eliminated physics tunneling through platforms.
- **Hitbox Accuracy Without External Physics:** Detecting high-speed sword slashes without relying on physics engines required calculating swept bounding volumes to prevent attacks from clipping past fast-moving enemies between frames.
- **Solo Scope Management Under Hackathon Deadlines:** Building an engine, authoring sprite animations, scripting three boss encounters, and balancing combat feel solo within a tight hackathon window required strict prioritization of core gameplay mechanics over secondary visual flourishes.

## Outcome

- **Top 5 Finalist at UTM Hackathon 2026**, built and submitted entirely as a solo developer.
- Engineered a lightweight, zero-dependency browser action game that starts instantly with 60 FPS performance across modern desktop browsers.
- Delivered a complete three-stage campaign featuring two mini-bosses, a climactic final boss encounter, and responsive swordplay mechanics.
